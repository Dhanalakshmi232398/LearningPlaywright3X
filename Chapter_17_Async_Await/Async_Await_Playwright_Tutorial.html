Async JavaScript with Playwright

A practical tutorial for reading asynchronous test code, choosing between sequential and parallel work, and handling browser events.

The central idea: Playwright talks to a browser over asynchronous APIs. JavaScript starts an operation, waits for its result, and then continues the test.

Examples below use the Playwright Test runner. Save JavaScript examples as a .spec.js file and run them with npx playwright test.

Sequential
Use when the next step needs the previous result.
Parallel
Use when operations are independent.
Events
Start waiting before the action that creates the event.

1. async

An async function always returns a Promise. In Playwright, a test callback is commonly marked async so it can use await.

import { test, expect } from '@playwright/test';

test('opens the Playwright home page', async ({ page }) => {
    await page.goto('https://playwright.dev/');
    await expect(page).toHaveTitle(/Playwright/);
});

Even if an async function returns a plain value, JavaScript turns it into a resolved Promise:

async function getEnvironment() {
    return 'test';
}

getEnvironment().then(value => console.log(value)); // test

2. await

await pauses the current async function until a Promise settles, then gives you its resolved value. It makes asynchronous steps read from top to bottom.

test('logs in', async ({ page }) => {
    await page.goto('https://example.com/login');
    await page.getByLabel('Email').fill('student@example.com');
    await page.getByLabel('Password').fill('secret');
    await page.getByRole('button', { name: 'Log in' }).click();

    await expect(page.getByRole('heading', { name: 'Dashboard' })).toBeVisible();
});
Important: await does not block the whole JavaScript process. It pauses this async function while the browser operation is in progress.

3. Promise.all

Use Promise.all when several Promises are independent. They start together, and the result array keeps the same order as the input array. If one rejects, the combined Promise rejects.

test('loads independent data together', async ({ page, request }) => {
    const [homeResponse, healthResponse] = await Promise.all([
        page.goto('https://example.com/'),
        request.get('https://example.com/health')
    ]);

    expect(homeResponse.ok()).toBeTruthy();
    expect(healthResponse.ok()).toBeTruthy();
});

For a browser event, create the wait first, trigger the action second, then await both:

const downloadPromise = page.waitForEvent('download');
await page.getByRole('button', { name: 'Download' }).click();
const download = await downloadPromise;
await download.saveAs('artifacts/report.pdf');

4. Promise.race

Promise.race settles with the first Promise to settle, whether that result is success or failure. It is useful for a timeout or for waiting for whichever UI state appears first.

function timeout(milliseconds) {
    return new Promise((_, reject) => {
        setTimeout(() => reject(new Error('Timed out')), milliseconds);
    });
}

test('waits for success or timeout', async ({ page }) => {
    await page.goto('https://example.com/');

    await Promise.race([
        page.getByText('Report ready').waitFor(),
        timeout(5000)
    ]);
});
Careful: the losing Promise is not automatically cancelled. Prefer Playwright's own timeouts for normal locator assertions, and use Promise.race when you genuinely need first-result behavior.

5. new Promise

new Promise adapts callback-style or custom asynchronous work into a Promise. Call resolve on success and reject on failure.

function waitForTestData() {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            const data = { username: 'alex' };
            data ? resolve(data) : reject(new Error('No data'));
        }, 300);
    });
}

test('uses custom asynchronous data', async ({ page }) => {
    const data = await waitForTestData();
    await page.getByLabel('Username').fill(data.username);
});

Do not wrap a Playwright method in new Promise just to await it. Methods such as page.goto, locator.click, and expect(...).toBeVisible already return Promises.

6. Callback

A callback is a function passed to another function so it can be called later. Playwright uses callbacks for test bodies and event listeners.

test('handles a console message', async ({ page }) => {
    const messages = [];

    page.on('console', message => {
        messages.push(message.text()); // callback runs when the event occurs
    });

    await page.goto('https://example.com/');
    expect(messages).toContain('Page loaded');
});

The function message => { ... } is the callback. It does not run when it is registered; Playwright calls it later when the browser emits a console event.

Putting It Together

import { test, expect } from '@playwright/test';

test('combines async patterns', async ({ page }) => {
    const consoleMessages = [];
    page.on('console', message => consoleMessages.push(message.text()));

    await page.goto('https://example.com/');

    const [title, heading] = await Promise.all([
        page.title(),
        page.getByRole('heading').first().textContent()
    ]);

    expect(title).toContain('Example');
    expect(heading).toBeTruthy();
});

Quick decision guide

  • Use async on a function that performs asynchronous work.
  • Use await when the next line depends on the result.
  • Use Promise.all for independent operations that should run together.
  • Use Promise.race when the first settled result should decide the flow.
  • Use new Promise to adapt callback APIs or custom timers.
  • Use a callback when an event or API will call your function later.
